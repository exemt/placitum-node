# internal/audit

Событие `kind=request` в поток `WAF_AUDIT`. Схема датаграммы —
docs/messages/agent.schema.ts (`docs/messages/agent.schema.ts`),
разбор — `docs/messages/module-agent.md`.

Обычный `PUB` на `waf.audit.request.<node_id>`.

Агент — прозрачный ретранслятор. Датаграмма модуля это уже готовая запись
аудита, поэтому она уходит на шину **как есть**: `Envelope` вставляет
`"v":1,"kind":"request"` перед первым полем, и всё. Раскладывать сообщение в
структуру и собирать заново нельзя — так теряется всё, чего в структуре не
оказалось (секция `store` терялась именно так), а схему приходится держать в
двух местах сразу.

`Decode` читает ровно то, без чего сообщение не отправить: `node` для subject,
`ray` и `verdict` для отбраковки неполной записи, `http.status` для счётчика
трафика, `store.archive` и `ts` для архивации. Остальные поля агент не толкует.

`store.go` — единственное исключение из «как есть», и оно тоже точечное.
Когда модуль передал агенту объекты обменника (`store.archive` непусто), их
локаторы после переезда в архив надо подменить. `SpliceStore` вырезает пролёт
значения `"store"` верхнего уровня и ставит на его место собранный заново;
остальная запись не разбирается вовсе. `Readdress` и `Unreachable` работают с
одним локатором: меняют адресацию либо сносят её вместе с причиной, сохраняя
описание и все незнакомые поля в исходном порядке.

Сама архивация живёт в [internal/retain](../../../../agent/internal/retain): здесь только форма
записи.

Имя узла подставляется, только если модуль его не прислал: повторное поле
`node` в объекте сделало бы смысл записи зависимым от порядка разбора.

Агент сам запрос не видит и вердикт не считает.
