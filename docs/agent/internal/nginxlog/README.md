# internal/nginxlog

Второй unix datagram ноды. Кладёт туда строки не модуль, а сам nginx своим
syslog-писателем (`access_log syslog:server=unix:…`), поэтому ни модуля, ни
хвоста файла в этой дороге нет.

Путь по умолчанию — `/var/run/waf/log.sock` (`log_sock`, `WAF_LOG_SOCK`).
Пустое значение или `log_sock off` выключает приёмник.

## Что делает

`Parse` снимает шапку RFC 3164: уровень из приоритета, сервис из тега, остальное
— текст. Не разобралось — не ошибка: строка едет целиком в `text` и без уровня.
Молча выбросить лог, потому что его шапка не та, значит потерять ровно то, ради
чего в сокет смотрят.

Тег ищется не дальше двух полей от отметки времени: с `nohostname` он стоит
первым, без него вторым, а дальше начинается текст, в котором двоеточий сколько
угодно. Без этого потолка `*1 open() failed` отдал бы `failed` за имя сервиса.

Время строки ставит агент в момент приёма. В шапке нет ни года, ни зоны, ни
долей секунды; собственная отметка nginx остаётся внутри текста.

`Sink` копит строки и публикует их пачками на `waf.log.<node>`: 500 строк,
256 КБ или 200 мс, что раньше. Публикация — из своей горутины, читатель сокета
шину не ждёт. Буфер при недоступной шине — 20 000 строк, дальше выбрасывается
голова, и счётчик потерь виден в кадре присутствия (`log_dropped`).

## Чего не делает

| Не его | Кто |
| --- | --- |
| Формат строки и её уровень | nginx: `log_format`, `error_log <level>` |
| Имя сервиса | `tag=` в директиве nginx |
| Дедуп повторной доставки | никто: у строки лога нет ключа, см. `waf.log` |
| Журнал самого агента и прочих процессов | их собственный приёмник, см. ниже |

Приёмник здесь нужен потому, что своего клиента шины у nginx нет. У процесса,
который на шине уже сидит, дороги на сокет нет и не должно быть: он публикует
такую же пачку сам — `internal/logsink` у инспекторов, `src/logsink.py` у
питоновских. Форма на проводе, границы пачки и потолок буфера общие с этим
пакетом, потому что разбирает обе пачки один `model.FromLog`. Расхождение здесь
— молча пустая таблица.

Дорога целиком, включая таблицу и раздел UX —
`docs/logger/logs.md`.
