# Известные проблемы аудита

Временный файл. Каждая запись — расхождение с тем, как должен выглядеть
контур. Удаляется вместе с исправлением.

## Секция `audit` едет в вердикте волны впустую

**Симптом.** Ответ инспектора модулю (inbox волны, `PUB` на `reply-to` запроса
`waf.req.<inspector>`) несёт секцию `audit` — сырой CRS, `matched[]`,
`engine_ms`. Те же данные инспектор сразу после inbox сбрасывает в
`waf.audit.inspector.<name>`. Агент в `kind=request` их не видит и не
публикует. На карточке аудита UX склейка идёт по `node`+`rid` из двух топиков
потока, не из inbox.

**Причина.** Поле задумывалось для этапа 8: один писатель — модуль, он же
склеивает `inspector_audit` из ответов волны. Писателей разнесли: инспектор
пишет `kind=inspector` сам, модуль отдаёт агенту только итог фазы на
`waf_agent_socket`, агент публикует компактный `kind=request`. Парсер ответа
в модуле секцию `audit` пропускает как незнакомый ключ
(`ngx_http_waf_msg_reply.c`). Протокол по-прежнему говорит «метаданные для
лога», но лог через модуль больше не едет.

**Чего требует исправление.** Не класть `audit` в inbox. Собирать объект как
сейчас, маршалить в ответ волны без этой секции, полный объект оставить только
в `PUB waf.audit.inspector.*`. Версию схемы поднимать не надо: поле
необязательное, модуль его уже игнорирует.

**Что работает.** Решение волны — `verdict` / `score` / `reason` (и при
необходимости `response` / `headers`). Join аудита — `docs/audit.md#писатели`.
Сырые CRS scores живут в событии инспектора.

**Цена оставлять как есть.** `matched[]` раздувает ответ против `waf_reply_max`
и жрёт сериализацию в дедлайне волны. Модулю это не нужно.

## Нет сквозного ray uuid

**Симптом.** Инцидент ищется и склеивается по `node` + `rid`. На странице
отказа: `edge-01 · 480000013b000000`. Оператору нода в поиске атак не нужна:
не «кто», не «куда», не «чем отсекли». Без неё `rid` чужих краёв совпадает.

**Причина.** `rid` — слот воркера, не идентификатор запроса:

```
rid = (gen << 24) | index
```

Индекс общий на все ноды (слот `0` есть у каждого края). Поколение
случайное в воркере, не по флоту. Спека прямо говорит: уникален в пределах
узла и поколения процесса. Агент в `kind=request` эхоит то, что пришло с
`waf_agent_socket`: отдельного поля нет. Join `WAF_AUDIT` поэтому держит
`node` костылём уникальности.

**Чего требует исправление.** Сквозной `ray` — UUID (или 128-бит hex),
уникальный на флот. Рождается в воркере в момент слота: только он видит
запрос. Едет в сокет → `kind=request`, в сообщение инспекции →
`kind=inspector`, на страницу отказа вместо `edge-01 · rid`. `rid` на
горячем пути не трогать: по нему O(1) lookup слота. Агент поле не
выдумывает — публикует, как `rid`. Логгер и UX ищут по `ray`; `node`
остаётся в строке, в топы и фильтр инцидентов не входит.

**Что работает.** Волна, inbox, слоты. Локально на одной ноде `rid`
достаточен. На флоте — нет.
