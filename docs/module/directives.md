# Директивы модуля: что реализовано, что задекларировано, что впереди

Этот документ — срез директив nginx, привязанный к текущему состоянию кода `nginx/module/src`, а
не к спецификации продукта. Полное описание синтаксиса и семантики каждой директивы —
`docs/directives/list/` (`docs/directives/list`); переход инспекторов —
`docs/directives/2-plan.md`; этапы реализации —
`docs/roadmap.md`. Здесь эти два документа сведены в одну таблицу с
поправкой на реальный код: что уже работает, что объявлено, но ничего не делает, и что появится
только на следующих этапах.

**Инспекторы: новый API в модуле.** Реестр — `waf_inspector` (`subject=`, `profile=`, `audit=`,
`breaker=*`). Pipeline — `waf_inspect` (`wave=` обязателен). Старые имена и опции в «Снятые»:
конфиг с ними не грузится. Контроллер ещё печатает старые директивы.

Собрано по: `src/ngx_http_waf_module.c` (таблица `ngx_http_waf_commands`), `src/core/` (разбор и
слияние конфигурации), `src/runtime/` (горячий путь), `README.md`, `known-issues.md`. Сводный список
пробелов — не только директив, но и опций, полей протокола и инфраструктуры — в
[`unsupported.md`](unsupported.md).

## Легенда статусов

| Значок | Значение |
| --- | --- |
| ✅ | Директива есть в коде и влияет на поведение так, как описано |
| 🟡 | Директива есть в коде (парсится, валидируется, наследуется), но механизм, который она включает, ещё не реализован — значение принимается и ни на что не влияет |
| ⏳N | Директивы нет в коде; появится на этапе N по `roadmap.md` |
| ⚠ | Есть в коде, но отсутствует в `directives/list/` — деталь реализации, а не публичный API |

Незарегистрированная директива даёт ошибку при `nginx -t`, и это выбрано намеренно: принятая и
проигнорированная директива — это конфигурация, которая выглядит рабочей и таковой не является. По
той же причине `waf_bus` отвергает `tls=`, `tls_*=` и `creds=` с явным «not implemented yet», а не
молчит о том, что соединение с шиной осталось открытым.

## Снятые директивы

Переименованные и слитые директивы остались в таблице команд, но только чтобы сказать, чем их
заменили: конфигурация с любой из них не загружается. Молчаливая совместимость здесь была бы хуже
отказа — старое имя означало другую семантику, и принятый по нему конфиг защищал бы не то, что
написано.

| Снято | Чем заменено |
| --- | --- |
| `waf_body_store <name> ...` | `waf_store ...` — обменник один на конфигурацию, имя ему не нужно |
| `waf_body <name>\|off [allow_remote=]` | `waf_capture` для инспекторов, `waf_archive` для архива; привязки маршрута к обменнику больше нет |
| `waf_request_body_access on\|off` | `waf_capture request body` |
| `waf_response_body_access on\|off` | `waf_capture response body=<size>` — об отдельном разрешении говорит снимок |
| `waf_on_partial_rewrite <фаза> original\|store` | `waf_send <фаза> body=original\|store` — откуда отдать объект; неполный снимок из обменника не отдаётся — это сбой подъёма по `waf_exception <фаза> body`, опции «отдать кусок» больше нет |
| `waf_body_archive ... class= sample=` | `waf_archive request ... ttl=` |
| `waf_request_archive <objects> ...` | `waf_archive request <objects> ...` — область называется первым словом |
| `waf_headers_preview_allow <name>...` | `waf_preview headers ... allow=<names>` |
| `waf_headers_preview_deny <name>...` | `waf_preview headers ... deny=<names>` |
| `waf_headers_preview`, `waf_args_preview`, `waf_body_preview` | `waf_preview headers=30k/1k args=8k body=10k` — размер на объекте |
| `force` у превью | ничем: заданное превью само означает «извлечь» |
| `waf_on_timeout pass\|block` | `waf_exception <фаза> timeout pass\|deny` |
| `waf_body_max <size>` | `waf_body_limit <size> [block\|trim\|pass]` |
| `waf_on_body_oversize pass\|block\|truncate` | второе слово `waf_body_limit`; `truncate` стал `trim` |
| `waf_body_inline_max <size>` | ничем: на горячем пути она не читалась ни разу |
| `waf_log_format`, `waf_audit`, `waf_audit_body`, `waf_audit_mask` | запись аудита фиксированной схемы: срез -- `waf_preview`, маски -- `mask=`/`deny=` у `waf_capture`; сэмпл по исходу -- отдельная директива, когда понадобится |
| `waf_early_data`, `waf_body_encrypt`, `waf_status`, `waf_response_bypass` | ничем: были описаны в старом справочнике, в модуле не существовали; контроллер их больше не хранит и не печатает |

Старые имена инспекторов (конфиг не грузится):

| Снято | Чем заменено |
| --- | --- |
| `after=`, `sample=`, `placement=`, `role=`, `needs=`, `body=`, `headers=`, `timeout=`, `phase=` на `waf_inspector`; `weight=` где угодно | Реестр: `subject=`, `profile=`, `audit=`, `breaker=*`. Вызов: `waf_inspect` |
| `waf_request_inspectors`, `waf_response_inspectors` | `waf_inspect <name> wave=<n> [timeout=] [mode=] [phase=];` / `waf_inspect none;` |
| `waf_inspector_mode` | `mode=` на `waf_inspect`; нет строки — не бежит (`ignore` снят) |
| `waf_inspector_profile` | `profile=` на `waf_inspector` |
| `waf_inspector_allow_headers`, `waf_inspector_allow_cookies` | запретный список + санитайз + `waf_redirect_allow` + `waf_cookie_defaults` |

## Реализовано

Этапы 1–6 закрыты: запрос ждёт вердикта в access-фазе, клиент NATS живёт в цикле событий, граф и
волны считаются при загрузке, вердикт со счётом применяется целиком, локальный слой решает до
публикации на шину, тело запроса едет инспектору инлайном или через хранилище.

### Шина и протокол

| Директива | Контекст | По умолчанию | Статус | Примечание |
| --- | --- | --- | --- | --- |
| `waf_bus <url>[,<url>...] [опции];` | http | — | ✅ | Опции: `name=`, `user=`, `pass=`, `token=`, `connect_timeout=`, `reconnect_wait=`, `ping_interval=`, `pending_max=`, `payload_max=`. Адреса разрешаются при загрузке: воркеру резолвер недоступен, а `getaddrinfo` в цикле событий блокирует |
| `waf_node_id <string>;` | http | имя хоста | ✅ | Входит в имя инбокса: `_INBOX.waf.<node_id>.<pid>.<nonce>` |
| `waf_agent_socket <path>;` | http | — | ✅ | Unix dgram: итог фазы агенту. При `waf on` путь обязателен, иначе `nginx -t`. `sendto` без ожидания, промах не двигает запрос |
| `waf_reply_max <size>;` | http | `8k` | ✅ | Верхняя граница ответа инспектора; на неё же рассчитан буфер разбора |
| `waf_header_value_max <size>;` | http | `4k` | ✅ | Предел длины одного значения в переопределении |
| `waf_max_inflight <n>;` | http | `4096` | ⚠ ✅ | Размер таблицы слотов ожидания. Деталь реализации (кодирование `rid`), а не публичный API. Верхняя граница — `NGX_HTTP_WAF_SLOT_INDEX_MASK` |

`waf_bus_flush_interval` и `waf_protocol_versions` из спецификации не зарегистрированы: батчинг
публикаций и мультиверсионность нужны под нагрузкой, которой ещё не измеряли. Модуль публикует
версию 1 и принимает только её.

### Инспекторы, наборы, режимы

| Директива | Контекст | Статус | Примечание |
| --- | --- | --- | --- |
| `waf_inspector <name> subject=<subject> [profile=] [audit=] [breaker=*];` | http | ✅ | Реестр. Два имени на один subject — один процесс, разные профили. `:` в имени запрещён |
| `waf_inspect <фаза> <name> wave=<n> [timeout=] [mode=] [keep=] [resume=];` / `waf_inspect <фаза> none;` | http, server, location, замена набора **своей фазы** | ✅ | `mode=active\|passive\|vote\|off`; `vote` — совещательный: очки в сумму, `deny` как 100, сам не решает; `off` — не публикуется, пока сосед не поставит `active`/`passive`/`vote` управляющим глаголом; просить вправе любой инспектор, спрошенный на маршруте (docs/inspector-actions.md, «Управляющие глаголы»); `control=` и `when=` сняты. Фаза первым словом: `request`, `response`, `frame`, `frame:c2s`, `frame:s2c`. `frame` задаёт оба направления. `wave=` обязателен, `phase=` снят. `response` бежит: ответ удерживается фильтрами до вердикта. `frame:c2s` и `frame:s2c` бегут: обработчик апгрейда держит кадр до вердикта (`gate`), один кадр в полёте на соединение на обе стороны. `keep=on` — только на `request`, `resume=off|prefer|require` — только на потребляющей фазе; пара обязательна в обе стороны по эффективным маршрутам (листья после слияния). Работает: `keep=on` шлёт `resume.want`, вердикт может вернуть `continue` (личный subject, срок), поздняя фаза публикуется туда с ключом и `require`; `no_responders` при `prefer` возвращает её в групповой subject, при `require` — `waf_exception <фаза> absent`; состояния нет у живого экземпляра — `prefer` переигрывает, `require` отказывает|prefer\|require` — только на потребляющей фазе. Работает: фаза запроса шлёт `resume.want`, вердикт может вернуть `continue` (личный subject, ключ, срок), поздняя фаза публикуется туда; `no_responders` при `prefer` возвращает её в групповой subject |

### Дедлайны и политики

| Директива | Контекст | По умолчанию | Статус | Примечание |
| --- | --- | --- | --- | --- |
| `waf on\|off;` | http, server, location, наследуемая | `off` | ✅ | При `off` обработчик выходит сразу |
| `waf_route_id <uuid>;` | location; `if` внутри наследует | — | ✅ | Uuid пути из панели, модуль его не толкует: пишет в аудит как `route.id`. По нему журнал схлопывает трафик маршрута и пульс считает rps; имя блока рядом остаётся для чтения. Контроллер печатает его в каждый `location`, у каждого сервера есть обязательный корень `/`, поэтому без uuid запрос не остаётся |
| `waf_deadline <фаза> <time>;` | http, server, location, наследуемая | `50ms` у `request`, у остальных — значение `request` | ✅ | Бюджет фазы целиком, а не одной волны. Только срок: политика на истёкший бюджет и на молчание обязательного инспектора переехала в `waf_exception <фаза> timeout`, второе слово — `nginx -t` с подсказкой. Причина отказа переживает резолюцию: `ctx->fail_reason`. `waf_response_deadline` снята |
| `waf_hold <фаза> gate\|monitor;` | http, server, location, наследуемая | `gate` | ✅ на `response` и `frame:c2s` | Держим ли до вердикта. На фазе ответа работает: `gate` не отдаёт клиенту ни байта до вердикта, `monitor` отпускает ответ сразу и на отказе обрывает соединение. На кадрах клиента работает только `gate`: `frame:c2s monitor` — `-t`, несколько кадров в полёте машина слотов не держит. `request monitor` — `-t`: наблюдение без гейта это `mode=passive`. `waf_frame_mode*` и `waf_response_buffer_max` сняты |
| `waf_exception <фаза> [timeout\|absent\|bus\|body\|inspector\|overload] pass\|deny [response=<имя>];` | http, server, location, наследуемая | `timeout`, `absent`, `body`, `inspector`, `overload` — `deny`; `bus` — `pass` | ✅ | Одна директива на все причины «вердикта нет». Класс необязателен: строка без него задаёт все шесть, класс на уровне дважды — `nginx -t`. `absent` возникает по `NO_RESPONDERS` от шины; `bus` — только ошибки транспорта и исчерпанные слоты (битый ответ сюда не относится: он отбрасывается, и решает `timeout`); `body` — отказ хранилища, исчерпанный `waf_body_max_holds`, ошибка сбора тела и сорванный подъём подмены; `inspector` — `verdict: error` от самого инспектора (код `fail_inspector`): обязательный срывает волну сразу, не дожидаясь дедлайна, пассивный и совещательный не срывают ничего. `overload` — тот же `error`, но названный сбросом на входе (`reason.class: "overload"`, код `fail_overload`): очередь инспектора полна либо бюджет протух до начала работы. Политику недоступности запоминает тот, кто её обнаружил: по состоянию `oversize` от отказа хранилища не отличить. `response=` — запись каталога для `deny`; не названа — 503 без каталога |
| `waf_send <фаза> <headers\|args\|body>=original\|store ...;` | http, server, location, наследуемая, **слот на фазу и объект** | `store` у всех объектов на всех фазах; `original` — только явной строкой | ✅ | Откуда отдать объект получателю: как пришёл или последнюю версию инспектора из обменника (секция `rewrite` реплая). Четвёртая ось таблицы снимка. Заголовки и строка запроса — склейка `set`/`unset` по имени (секции `headers` и `args` реплая, через обменник не ходят); тело — объектом целиком (`rewrite.body`). Неполный снимок store не отдаёт никогда — это сбой подъёма, и решает его `waf_exception <фаза> body` (отказ `REWRITE_FAILED` при `deny`, оригинал при `pass`), `partial:true` в записи, WARN в логе; срез при **явном** `store` — WARN на `-t` (у подставленного умолчания предупреждения нет). Своего рычага на сбой у директивы нет: `on_error=` и `response=` сняты. `store` без снимка объекта — `-t`. `waf_on_partial_rewrite` снята |
| `waf_deny_mode <фаза> fast\|deterministic;` | http, server, location, наследуемая | `fast` | ✅ | В `fast` волна замыкается на первом `deny` обязательного инспектора; в `deterministic` дожидается всей волны |
| `waf_capture <фаза> <headers\|args\|body>[=<size>\|none] ... \| off;` | http, server, location, наследуемая, **слот на фазу** | `headers args` у `request`, у остальных фаз — ничего | ✅ | Что видят **все** инспекторы маршрута. В сообщении `needs` = объекты capture. В Redis `max(capture, archive, preview)`; локатор в JSON режет по размеру capture. Archive/preview в сообщение не добавляют. Mask/deny на `headers`/`args` — до put инспекторам; перед агентом модуль кладёт оригинал в те же ключи. Без `=` — весь объект; больше `client_max_body_size` / `waf_body_limit` — ошибка при `-t` |

### Скоринг

| Директива | Контекст | По умолчанию | Статус | Примечание |
| --- | --- | --- | --- | --- |
| `waf_score_deny <фаза> <n> [response=<name>];` | http, server, location, наследуемая | `0` (выкл.) | ✅ | Достижение порога замыкает фазу, не дожидаясь остальных волн. Сумма у каждой фазы своя; `waf_response_score_deny` снята |

При `nginx -t` проверяется, что названная в `response=` запись каталога объявлена: ненайденная запись
даёт отказ без страницы, и это дешевле поймать на загрузке.

Порог здесь один, и второго не будет. Из накопленного счёта модуль выводит только отказ; решение о
челлендже принимает сервис на шине по той же паре чисел, которую видит в секции `score`.

### Ответы, редиректы, диагностика

| Директива | Контекст | По умолчанию | Статус | Примечание |
| --- | --- | --- | --- | --- |
| `waf_deny_response <name> [type= status= page= message= code= reason=];` | http | — | ✅ | Статус вне 4xx/5xx для `type=http` отвергается: 2xx и 3xx превращают блокировку в тихий пропуск. `type=websocket` применяется на фазе кадров: код и причина кадра Close при отказе; `type=grpc` разбирается, но применяется с этапа 9 |
| `waf_deny_response_default <name>;` | http, server, location, наследуемая | `blocked` | ✅ | Ненайденная запись с этим именем даёт предупреждение, а не ошибку: до отказа может и не дойти |
| `waf_redirect_allow <шаблон>...;` | http, server, location, наследуемая | пусто (редирект запрещён) | ✅ | Формы: `/путь` и `scheme://host[:port][/prefix]`, хост допускает `*.` Заданный список заменяет родительский, а не дополняет |
| `waf_cookie_defaults [secure=] [http_only=] [same_site=];` | http, server, location, наследуемая | `secure=on http_only=on same_site=Lax` | ✅ | Атрибуты форсируются поверх присланных инспектором |
| `waf_debug_header on\|off;` | http, server, location, наследуемая | `off` | ✅ | `rid`, режим и латентность каждого инспектора, накопленный счёт, причина отказа, `body=` с местом размещения тела или причиной недоступности. Ставится и на ответе, закрытом политикой без вердикта: 503 от контура и 503 от приложения снаружи иначе неотличимы |

`waf_frame_score_deny` из спецификации не зарегистрирована: у фазы кадров нет ни волн, ни суммы
(этап 12), а принять порог и не применять его — хуже, чем не принять.

### Локальный слой

| Директива | Контекст | Статус | Примечание |
| --- | --- | --- | --- |
| `waf_shm_zone <name> <size>;` | http | ✅ | Одна на конфигурацию. Директива локального слоя без объявленной зоны — ошибка при `nginx -t`, а не молчаливое отключение проверки; зона ниже по файлу не помогает, потому что директива маршрута разбирается раньше |
| `waf_local_rate <key> rate=<n>r/s\|r/m burst=<n> [count=requests\|waves\|frames] [action=block\|pass] [response=<name>] [list=<dataset> ttl=<time>] [if <value> in\|not in <dataset>]…;`<br>`waf_local_rate none;` | http, server, location | ✅ | Протекающая корзина, как у `limit_req`. `list=` + `ttl=` — автобан ключа в overlay набора и событие на шину. `action=pass` с `list=` отвергается. Ключ — одно значение: селектор `*` отвергается. Наследование заменой, `none` снимает родительские. `count=frames` — правило считает спрошенные кадры WebSocket и на рукопожатии не смотрится; `requests` и `waves` на кадрах не смотрятся |
| `waf_local_dataset <name> [type=cidr\|string] [limit=<n>] [ttl=<time>] active\|internal;` | http | ✅ | До 128 наборов, больше -- `nginx -t` падает. Слот стыкуется по имени; тема `active` набора — `waf.sets.<name>` у keeper, `subject=` отвергается. Overlay до 10000 записей. Разметка зоны меняется: нужен restart. `type=regex` отвергается |
| `waf_local_check <dataset> <value> action=block\|allow\|wave [response=<name>] [if <value> in\|not in <dataset>]…;`<br>`waf_local_check none;` | http, server, location | ✅ | Порядок объявления и есть приоритет, первое сработавшее решает: сначала все проверки, потом все лимиты. Значение — переменная nginx или селектор `$waf_request_{args,cookies,headers}.<имя>`. Наследование заменой, `none` снимает родительские. Исход локального слоя — только отказ или пропуск: увести клиента на челлендж он не может, потому что
это решение сервиса, а здесь о запросе ещё не знает никто.

`response=` у `waf_local_rate` — добавление к первоначальной спецификации, а не деталь реализации:
превышение частоты стоит отвечать `429`, потому что клиент может исправить это сам, и отвечать ему тем
же, чем отвечает блокировка, значит скрывать от него единственное, что он способен изменить.

Счёт по волнам начисляется после публикации: отменять волну там уже поздно, и превышение учитывается
на следующем запросе того же ключа. Начисление за волну записывается и за пределом всплеска — иначе
корзина упирается во всплеск, накопленное никогда его не превышает, и проверка не срабатывает вовсе;
сверху долг ограничен секундой частоты сверх всплеска.

Наборы приезжают с keeper (`docs/keeper.md`): воркер подписан на `waf.sets.<name>`,
применяет дельты по номерам и сверяет `(epoch, seq, hash)` на каждом кадре и на тике; снапшот
страницами и хвост `since` идут запросом с ответом в инбокс. Разрыв нумерации приводит к запросу
хвоста, чужая эпоха или расхождение хеша — к снапшоту, не чаще одного на набор в десять секунд —
отметка в зоне, поэтому предел общий для воркеров, а не свой у каждого. Обновление применяет первый успевший воркер, остальные отбрасывают его по
номеру; читатели при этом не блокируются, а прежний набор освобождается, когда его отпустит последний.

Circuit breaker (`breaker*=` у `waf_inspector`) тоже относится к этому этапу: состояние живёт в той же
зоне и общее для воркеров. Без зоны предохранителя нет — держать его в памяти воркера было бы хуже,
чем не держать вовсе, потому что воркеры расходились бы в решениях.

Счётчики слоя (блокировки, пропуски по разрешающему набору, попадания и отвергнутые обновления по
каждому набору) накапливаются в зоне, но наружу их пока не отдаёт ничто: `waf_status` — этап 13. До
него всё это видно только в логе.

Локатор в сообщении — объект store (`store`, `driver`, `key`, `size`, для тела ещё `sha256`) либо
`null`: объекта нет, маршрут его не снимает или этот инспектор его не просил. Поля `inline` модуль
больше не пишет. `unavailable` с причиной — когда объект есть, но недоступен. Тихая потеря означала
бы тихое отключение проверки.

Три ключа в том же store: тело `<node>:<rid>:<phase>`, заголовки `<node>:<rid>:<phase>:hdr`, строка
запроса `<node>:<rid>:<phase>:arg`. Позиционные, не хеш содержимого: хеш требовал бы полного прохода
до начала записи. Строка запроса лежит сырой, как пришла: разбор на пары — интерпретация, и модуль,
выбрав одну, навязал бы её всем инспекторам. Все снимаются сразу после разрешения вердикта, а не в
конце ответа. `ttl=` обменника — страховка от падения воркера между размещением и удалением.
`waf_body_max_holds` считает каждый объект.

Исключение — `waf_archive`: названные в нём объекты модуль не удаляет, а передаёт их агенту
вместе с записью аудита (`store.archive` на проводе, см.
`docs/messages/module-agent.md`). Агент перекладывает их
в архив, подменяет локаторы архивными и чистит обменник сам. Модуль про архив не знает ничего, кроме
срока хранения: ни адреса, ни реквизитов, ни бакета — иначе смена хранилища требовала бы правки
`nginx.conf` на каждой ноде.

Архив не подчинён `waf_capture`: названный в нём объект снимается потому, что его назвали, и в
сообщение инспекторам не добавляется. Тело ради архива читается так же принудительно, как ради
`waf_preview body`, и точно так же встречается с `waf_body_limit` — прочитать больше предела не
выйдет ни для кого.

Размер на объекте (`body=8k`) режет не модуль, а агент. В обменнике объект лежит по
`max(capture, archive, preview)`. Агент читает объект, обрезает до размера перед записью и помечает
урезанное, чтобы читатель записи не принял префикс за оригинал. Общий `limit=` снят: иначе одна
строка не могла бы резать только тело.

Три следствия, которые стоит знать при настройке. Наследование сентинельное: набор не задан — берётся
родительский, `none` — явное «здесь ничего», и оно тоже наследуется. Строки одного уровня
складываются по объектам, а `none` очищает уровень целиком; `ttl=`, `when=` и размер на объекте
привязаны к названным в той же строке видам, потому что уточняют их, а не набор в целом. Удерживаемый объект
кладётся сразу с `retain_ttl=` вместо `ttl=`: политика маршрута
известна до `SET`, и на маршруте, где архивация *возможна*, длинный срок ставится всегда, даже при
`when=deny`. Если записи аудита не будет вовсе — запрос оборвался до вердикта, — удерживать некому, и
объект удаляется как обычный.

Заголовки и строка запроса размещаются одним заходом цикла событий: драйвер складывает команды в
свой буфер и сбрасывает разом, поэтому второй `SET` не ждёт ответа на первый. Тело — отдельным
заходом: разместить его раньше, чем прочитать, нельзя, а читается оно намеренно поздно, чтобы волна
0 не платила за тело, которого её инспекторы не просили. Объектов три, round-trip по-прежнему два.

### Превью в записи аудита

| Директива | Контекст | По умолчанию | Статус | Примечание |
| --- | --- | --- | --- | --- |
| `waf_preview <фаза> <headers\|args\|body>=<size>[/<item>]\|none ... \| none;` / `waf_preview <фаза> headers\|args allow=\|deny=` / `waf_preview response\|frame body=<size> source=sent\|original` | http, server, location, наследуемая | `off` у всех трёх, `source=original` | ✅ | Область первым словом: `request`, `response`, `frame`/`frame:c2s`/`frame:s2c` (у кадра только `body`, срез может быть шире снимка, `reload` — `nginx -t`). Записей аудита столько, сколько фаз бежало, и бюджет датаграммы считается на каждую. Заголовки ответа в срезе — те же, что видит снимок. Бюджет секции в байтах **записанного JSON**. Размер обязателен. Списки имён — отдельные строки, есть у headers и args. Запрет сильнее. `source=sent` (response/frame body): в записи доставленная версия подменённого тела, оригинал в архиве, помечается `body_preview_source` |

Заданное превью — требование извлечь: названный объект окажется в записи, даже если его не просит ни
один инспектор волны. Отдельного `force` поэтому нет, а умолчание — `off`: превью, включённое по
недосмотру, стоило бы чтение тела на каждом запросе маршрута. Размер обязателен: без него
`nginx -t` отказывает. `=none` выключает секцию.

`item_max` — потолок на одну пару, считается по тем же байтам записанного JSON, что и бюджет секции.
Правило умышленно несимметрично к имени и значению: сначала пишется имя, и если имя занимает больше
половины потолка, пара выбрасывается целиком, а не обрезается. Имя такой длины само по себе улика, и
обрезок значения при нём ничего не добавит; обрезать же имя значило бы получить ключ, по которому
не ищется ни один запрос. Уложившееся имя оставляет остаток потолка значению: оно урезается по
границе символа UTF-8 и помечается урезанным.

`allow=` и `deny=` — только у заголовков и только через запятую в одном аргументе, потому что стоят
рядом с бюджетом той же секции. `allow=*` разрешает все, `deny=none` не запрещает ничего; перепутанные
слова (`deny=*`, `allow=none`) отвергаются, а не понимаются как пустая секция — для неё есть `off`.
Заданный запрет складывается со встроенным `authorization proxy-authorization cookie set-cookie`, а не
заменяет его: оператор, добавляющий имя, добавляет правило. Запрет сильнее разрешения — имя из `deny=`
не попадает в превью вовсе, и следа в виде ключа с меткой не остаётся.

Превью — не обменник: оно едет в самой записи аудита, живёт в ClickHouse сроком таблицы и ищется поперёк
всех записей сразу. Ось `waf_capture` его не касается — срез считается прямо из запроса, а не из того,
что легло в хранилище, иначе выключенный обменник молча выключал бы и запись.

Бюджет маршрута — не первое ограничение, а последнее. Выше него стоят абсолютные пределы чтения
самого WAF, и потолок каждой секции берётся оттуда: заголовки —
`large_client_header_buffers.num * .size`, строка запроса — размер одного такого буфера, тело —
`min(client_max_body_size, waf_body_limit)` (при `client_max_body_size 0` — только размер из
`waf_body_limit`). Названный здесь же размер сверх потолка — ошибка при `nginx -t`: оператор описывал
запись, которой не бывает. Унаследованный сверху — молча урезается: маршрут, опустивший
`waf_body_limit`, не переписывал превью и не обязан его повторять.

Сумма трёх бюджетов — это размер датаграммы агенту, и `nginx -t` проверяет её против потолка в 8 МБ
(`NGX_HTTP_WAF_AUDIT_DGRAM_MAX`, обязан совпадать с `handoff.MaxBytes` агента; на превью остаётся
`NGX_HTTP_WAF_PREVIEW_MAX` — те же 8 МБ минус место под саму запись). Превышение отвергается на
загрузке, потому что обрезанная датаграмма теряется у читателя молча. Чаще всего к нему приводит
превью без размера при щедром `client_max_body_size`: предел объекта становится бюджетом, и три таких
бюджета складываются в мегабайты. Лечится тем, что размеры называют явно.

Датаграммы в 8 МБ ядро по умолчанию не пропускает: `net.core.wmem_max` обычно около 208 КБ, и
`setsockopt(SO_SNDBUF)` молча урезается до него. Модуль перечитывает буфер после установки и пишет в
лог предупреждение, если получил меньше потолка, — поднимать `net.core.wmem_max` и `rmem_max` нужно
на ноде, конфигурацией nginx это не лечится.

Проверки при `nginx -t` перечислены в
`docs/body-storage.md` и реализованы все, кроме
относящихся к нереализованным механизмам (`waf_body_encrypt`, staging-store, `proxy_request_buffering
off`). `waf_body_limit` больше `client_max_body_size` — ошибка: тело сверх nginx-предела до модуля
не доходит (`413`), и описывать такое чтение незачем. Ноль в `client_max_body_size` — без предела.

## Этап 7 — Фаза ответа

Фаза бежит. `HEADER_FILTER` и `BODY_FILTER` подключены, ответ удерживается до вердикта
(`r->buffered`, бит делится с `image_filter` — поле четырёхбитное), отказ собирается заново
через `ngx_http_filter_finalize_request()`, то есть отдаётся страницей каталога тем же путём,
что отказ фазы запроса. `waf_hold response monitor` отпускает ответ немедленно и на отказе
обрывает соединение. `redirect` на этой фазе отбрасывается с предупреждением.

Инспектор получает `response.status` и контекст запроса секцией `request_store`. Заголовки
ответа едут инлайном (`set-cookie` не отправляется) только там, где фаза их не снимает: при
`waf_capture response headers` вместо инлайна едет локатор обменника — с `mask=` / `deny=`, как у
запроса. Тело — всегда локатором.

Снимок фазы работает: `waf_capture response headers|body` кладёт объекты в обменник под ключами
`<node>:<rid>:rsp` и `<node>:<rid>:rsp:hdr`, `waf_archive response` оставляет их агенту на
`retain_ttl`, `waf_preview response` пишет срез в запись аудита этой фазы. Записей аудита
столько, сколько фаз бежало. Заголовки ответа собираются из `headers_out` плюс `Content-Type`
и `Content-Length`, которые nginx держит отдельными полями. `waf_strip_accept_encoding`
подменяет значение на `identity` перед проксированием и возвращает клиентское до фильтра
сжатия: апстрим не сжимает, клиент своё сжатие не теряет.

| Что осталось | Почему |
| --- | --- |
| `waf_response_bypass` | заменён безусловным обходом (подзапрос, `header_only`, 204/304, `101`, своя страница отказа) и `waf_inspect response none`; отдельные условия вроде `partial` пока не разбираются |
| `headers.set` / `headers.unset` от инспектора | список запроса уже отправлен апстриму; правка отбрасывается с записью в лог |
| трейлеры | читаются после тела, к вердикту их ещё нет |

## Этап 10 — ICAP

Директив у этого этапа не осталось. Капча-специфики в модуле нет вовсе: сервис челленджа — обычный
инспектор, объявленный `waf_inspector`, а всё, что модуль о челлендже знает, — это `waf_redirect_allow`,
реализованный на этапе 4. Счётчик попыток, маркеры и разрыв цикла живут в сервисе, потому что модулю о
них знать нечем.

`waf_cookie_defaults` реализована раньше исходно запланированного этапа: атрибуты cookie нужны для
`Set-Cookie` от любого инспектора. Опция `domain=` при этом не поддержана.

Опция `body=full` у `waf_inspector` относится к ICAP-гейтвею и приобретает
практический смысл только с референсным сайдкаром этого этапа. Тело он читает
из Redis, как остальные инспекторы.
