# Дымовой прогон модуля

```sh
node nginx/tests/smoke/run.mjs
```

Один контейнер с собранным модулем, свой эфемерный порт, ни шины, ни обменника,
ни чужих стендов. Пять секунд.

## Зачем он отдельно от nginx -t

`nginx/tests/unit` проверяет разбор конфигурации: `nginx -t` не создаёт ни
одного контекста запроса и не вызывает ни одного обработчика фазы. Всё, что
живёт в горячем пути — жизненный цикл `ctx`, локальный слой, разрешение
вердикта, диагностический заголовок, строка итога, — для него невидимо.

Полный контур проверяют tests/e2e (`tests/e2e`) и
[nginx/tests/load](load/README.md), но обоим нужен поднятый стенд: NATS,
Redis, инспекторы, приложение. Дымовой прогон закрывает середину: живой
трафик через модуль, но без единой внешней зависимости.

## Что проверяется

| | |
| --- | --- |
| allow | 200, `X-WAF-Debug: v=allow`, строка `waf: allow phase request` |
| локальный отказ | 403 из каталога, `v=deny`, `local block by dataset "badua"` |
| локальный allow | тот же UA проходит: разрешающая проверка объявлена выше |
| `capture none` + `inspect none` | маршрут работает, в обменнике ничего |
| повторные запросы | двадцать запросов подряд в одном соединении |
| лог | ни `[alert]`, ни `[emerg]`, ни падений воркера; `ray` свой у каждого запроса |

## Ловушка, из-за которой прогон и появился

Маршруты конфигурации отдают файл, а не `return 204`.

`return` исполняется модулем rewrite на фазе `NGX_HTTP_REWRITE_PHASE`, то есть
**до** `NGX_HTTP_ACCESS_PHASE`, где стоит обработчик WAF. На маршруте с
`return` модуль не вызывается ни разу: `nginx -t` такой конфиг принимает,
запрос проходит мимо защиты, и по кодам ответов это неотличимо от «инспекторы
ничего не нашли».

В `nginx/tests/unit` `return 204` уместен — там проверяется только загрузка
конфигурации. В любом прогоне с трафиком маршрут обязан иметь настоящий
обработчик содержимого: `root`, `alias` или `proxy_pass`.
