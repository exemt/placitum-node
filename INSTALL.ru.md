# Установка

[English](INSTALL.md) · Русский

Узел ставят вместе с остальным Placitum: без шины, буфера и контроллера от него мало толку. Обычно
его поднимает `placitum-core` одной командой. Этот документ — для случая, когда узел ставят
отдельно, например вторым узлом к работающей установке.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS с JetStream | да | волны инспекторов, аудит, журнал, конфигурация из KV, присутствие |
| Redis: буфер | при `waf_capture`, `waf_archive` и превью тела | тело, заголовки и строка запроса на время волны |
| Redis: внутренний | желательно | блобы поколения от контроллера; без него они читаются из буфера |
| Контроллер | да | присылает конфигурацию; до этого узел отвечает заглушкой |
| S3-совместимое хранилище | при `waf_archive` | архив тел, заголовков и строки запроса |
| Инспекторы | те, что названы на маршрутах | модуль сам ничего не детектит |

## Как узел получает конфигурацию

Агент следит за поколением в JetStream KV (`WAF_DESIRED`, ключ `policy/nginx-pack`), собирает новое
дерево рядом с боевым, проверяет его `nginx -t` тем же бинарём с тем же модулем и применяет через
`nginx -s reload`. Кадр присутствия (`WAF_STATUS.node.<узел>.agent`) говорит, применилось ли
поколение: `ok`, `apply_failed` или `undecryptable`. Свежая нода сама забирает
текущее поколение, применять заново ничего не нужно.

Поколение, которое не применилось, агент пробует снова сам: через 2 секунды, потом с паузой, которая
удваивается до минуты. Его блобов может ещё не быть в Redis, или имя апстрима ещё не резолвится.
Более новое поколение сразу занимает его место.

До первого поколения nginx держит заглушку на `:8079`: `/healthz` отвечает `bootstrap`, остальное —
`503 waiting for controller generation`. Порты, серверы и маршруты приходят с поколением.

`WAF_NGINX_MANAGE=off` (или `manage off` в блоке `nginx`) снимает с агента конфигурацию и оставляет
ему аудит, архив, журнал и присутствие.

## Настройки

Агент читает `agent.conf`, затем окружение; переменная перекрывает тот же ключ файла.

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `WAF_NODE_ID` | нет | имя узла на шине, в панели и в аудите; **обязано совпадать** с `waf_node_id` в конфигурации модуля |
| `WAF_AGENT_CONFIG` | `/etc/waf/agent.conf` | файл конфигурации агента |
| `WAF_NGINX_MANAGE` | `on` | ведёт ли агент конфигурацию nginx |
| `WAF_AGENT_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |
| `WAF_NGINX_DEBUG` | `off` | `on` поднимает мастер из `nginx-debug`, чтобы `error_log debug` показывал события ядра, а не только строки модуля; читается при старте контейнера |
| `WAF_NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `WAF_REDIS_URL`, `WAF_REDIS_INTERNAL_URL` | из `agent.conf` | буфер и внутренний Redis |
| `WAF_NODE_KEY` | из `agent.conf` | приватный ключ установки: им расшифровываются секреты поколения |
| `WAF_DATA_DIR` | `/var/lib/waf/agent` | состояние агента: применённое поколение, очереди |
| `WAF_STORE_DIR` | `/var/lib/waf/store` | куда пишутся файлы поколения (сертификаты, ключи) |
| `WAF_VERDICT_SOCK`, `WAF_LOG_SOCK` | `/var/run/waf/verdict.sock`, `/var/run/waf/log.sock` | итоги от модуля и строки журнала nginx; пустой `WAF_LOG_SOCK` выключает приёмник журнала |
| `WAF_HEARTBEAT_EVERY` | `4s` | период кадра присутствия |
| `WAF_RETAIN_S3_ENDPOINT`, `WAF_RETAIN_S3_REGION`, `WAF_RETAIN_BUCKET_HEADERS`, `WAF_RETAIN_BUCKET_ARGS`, `WAF_RETAIN_BUCKET_BODY` | из `agent.conf` | хранилище архива |
| `WAF_RETAIN_WORKERS`, `WAF_RETAIN_QUEUE`, `WAF_RETAIN_OP_TIMEOUT`, `WAF_RETAIN_BATCH_HEADERS`, `WAF_RETAIN_BATCH_ARGS`, `WAF_RETAIN_BATCH_BODY` | из `agent.conf` | темп архива |

Реквизиты S3 — файлом (`/run/secrets/waf_s3_creds`, формат AWS-профиля), а не переменной: окружение
процесса видно соседям по машине и уходит в дампы.

## agent.conf

[agent/agent.conf](agent/agent.conf) — рабочий пример с комментариями: блоки `node`, `nats`, `redis`,
`s3`, `archive` и `nginx`. Один файл служит всем узлам установки, различия задаёт окружение. Блок
`redis` — той же формы, что у инспекторов: `url` — буфер, `internal` — внутренний Redis. Адрес,
регион и бакеты S3 и темп архива может перекрыть контроллер через KV (`policy/agent-conf`),
реквизиты — никогда.

## Docker Compose

```yaml
services:
  edge:
    image: placitum/node
    hostname: edge-01
    environment:
      WAF_NODE_ID: edge-01
      WAF_AGENT_CONFIG: /etc/waf/agent.conf
      WAF_NATS_URL: nats://nats:4222
    ports: ["80:8080", "443:8443"]
    volumes:
      - ./agent.conf:/etc/waf/agent.conf:ro
      - ./node.conf:/etc/nginx/waf-node.conf:ro
      - edge-data:/var/lib/waf/agent
      - edge-store:/var/lib/waf/store
    secrets: [waf_node_key, waf_s3_creds]
    tmpfs:
      - /var/cache/nginx/client_temp:rw,size=64m,mode=0700,uid=101,gid=101
```

`node.conf` — одна строка `waf_node_id edge-01;`: идентичность узла для модуля. Шину и всё остальное
печатает поколение; второй `waf_bus` здесь сделал бы `nginx -t` ошибкой.

**tmpfs важен, если тела больше `client_body_buffer_size`.** Модуль дочитывает такое тело из файла
синхронно, в цикле событий, и на диске это стоит задержки каждому запросу. `size` тоже оставьте:
страницы tmpfs — память контейнера, и без предела каталог утащит воркеров в OOM.

## Проверка

```sh
# 1. Узел поднят и до первого поколения отвечает заглушкой
curl -fsS http://127.0.0.1:8079/healthz        # bootstrap

# 2. Модуль в образе
docker exec <контейнер> ls /etc/nginx/modules/ngx_http_waf_module.so

# 3. Агент виден: кадр присутствия на шине
nats sub 'WAF_STATUS.node.>' --count 1

# 4. После раскатки поколения из панели конфигурация применилась
docker exec <контейнер> nginx -T | head -20
```

Здоровый агент пишет в журнал подключение к шине, затем `desired applied` с ревизией.
`apply_failed` в кадре присутствия значит, что поколение приехало, но не применилось: блобов нет или
`nginx -t` его отверг. Причина — в журнале агента, рядом `retry_in`, пауза до следующей попытки.

## Типичные ошибки

- **Имя узла в двух местах**: `WAF_NODE_ID` у агента и `waf_node_id` в конфигурации модуля.
  Разойдутся — панель покажет узел под одним именем, а аудит запишет под другим.
- **Агент — главный процесс контейнера.** Если шина недоступна на старте, агент завершается, и
  контейнер останавливается вместе с ним; поднимает его политика перезапуска.
- **Версия nginx.** Модуль собирается против конкретных исходников nginx, и в другую версию nginx
  его не загрузит. `NGINX_VERSION` сборки и версия базового образа — одно число, и меняются они
  вместе; новой версии нужен и свой `NGINX_SHA256`.
- **У заглушки свой порт.** `:8079` не спорит с портами, которые придут с поколением.
