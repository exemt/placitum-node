# Установка

Узел защиты ставят вместе с контуром: без шины, обменника и контроллера он не полезен. Здесь —
что должно быть рядом, чем это называется и как убедиться, что узел встал.

Обычно узел поднимает фундамент установки (`placitum-core`) одной командой. Этот документ — для
случая, когда узел ставят отдельно: рядом с чужим nginx, в свой кластер или вторым узлом к уже
работающему контуру.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS с JetStream | да | волны инспекторов, аудит, журнал, конфигурация из KV, пульс |
| Redis: обменник | при `waf_capture` | тело, заголовки и строка запроса на время волны |
| Redis: внутренний | да | блобы поколения конфигурации от контроллера |
| Контроллер | да для управляемого узла | присылает поколение; без него узел отвечает заглушкой |
| S3-совместимое хранилище | при `waf_archive` | архив тел, заголовков и строки запроса |
| Инспекторы | нужные из списка | иначе проверять некому: модуль сам ничего не детектит |

## Два вида узла

**Управляемый** (`WAF_NGINX_MANAGE=on`) — конфигурацию ведёт контроллер: агент пишет её на диск,
проверяет `nginx -t` и применяет `nginx -s reload`. Это раскладка по умолчанию, и это то, что
собирает `managed/Dockerfile`.

**Неуправляемый** (`off`) — конфиг лежит файлом, вы правите его сами; агент ведёт только аудит,
архив, журнал и пульс. Годится, когда nginx уже кем-то управляется.

До первого поколения управляемый узел поднимает заглушку на `:8079`: `/healthz` отвечает
`bootstrap`, остальное — `503 waiting for controller generation`. Порты, серверы и маршруты
приезжают из панели.

## Переменные

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `WAF_NODE_ID` | — | имя узла на шине, в панели и в аудите. **Обязано совпадать** с `waf_node_id` в конфиге модуля |
| `WAF_AGENT_CONFIG` | `/etc/waf/agent.conf` | конфиг агента: шина, оба Redis, S3, архив, nginx |
| `WAF_NGINX_MANAGE` | `off` | ведёт ли агент конфигурацию узла |
| `WAF_AGENT_LOG` | `info` | стартовый уровень журнала агента; живьём его переставляет панель |
| `WAF_NGINX_DEBUG` | `off` | `on` поднимает мастер из `nginx-debug`: нужен, чтобы `error_log debug` показывал события ядра, а не только строки модуля. Стартовый — бинарь мастера на ходу не меняется |
| `WAF_NATS_URL` | из `agent.conf` | шина; окружение перекрывает файл |
| `WAF_REDIS_URL`, `WAF_REDIS_INTERNAL_URL` | из `agent.conf` | обменник и внутренний Redis |
| `WAF_NODE_KEY` | `/run/secrets/waf_node_key` | приватный ключ контура: им расшифровываются секреты поколения |
| `WAF_DATA_DIR` | `/var/lib/waf/agent` | состояние агента: применённое поколение, очереди |
| `WAF_STORE_DIR` | `/var/lib/waf/store` | каталог обменника на ноде |

Реквизиты S3 — файлом (`/run/secrets/waf_s3_creds`, формат AWS-профиля), а не переменной:
окружение процесса видно соседям по машине и уезжает в дампы.

## agent.conf

Один файл на все узлы установки; что в нём различается — задаёт окружение.

```
node   { key, data, heartbeat, verdict_sock, log_sock }
nats   { url }
redis  { url, internal }
s3     { endpoint, region, credentials, bucket headers|args|body }
archive{ workers, queue, timeout, batch ... }
nginx  { bin, conf_dir, store_dir }
```

Блок `redis` — та же форма, что у инспекторов: `url` — обменник, `internal` — внутренний Redis.
Адрес, регион, бакеты и темп выгрузки может перекрыть контроллер через KV; реквизиты — никогда.

## Docker Compose

```yaml
services:
  edge:
    image: placitum/node
    hostname: edge-01
    environment:
      WAF_NODE_ID: edge-01
      WAF_NGINX_MANAGE: "on"
      WAF_AGENT_CONFIG: /etc/waf/agent.conf
      WAF_NATS_URL: nats://nats:4222
    ports: ["80:8080", "443:8443"]
    volumes:
      - ./agent.conf:/etc/waf/agent.conf:ro
      - ./node.conf:/etc/nginx/waf-node.conf:ro
      - edge-data:/var/lib/waf/agent
      - edge-store:/var/lib/waf/store
    secrets: [waf_node_key, waf_s3_creds]
    tmpfs:
      - /var/cache/nginx/client_temp:rw,size=64m,mode=0700,uid=101,gid=101
```

`node.conf` — одна строка `waf_node_id edge-01;`: идентичность для модуля. Шину и всё остальное
печатает поколение контроллера, второй `waf_bus` здесь сделал бы `nginx -t` ошибкой.

**tmpfs обязателен, если тело больше `client_body_buffer_size`.** Модуль дочитывает такое тело из
файла синхронно, в цикле событий; на диске это стоит задержки каждому запросу. `size` тоже
обязателен: страницы tmpfs — память контейнера, и без предела каталог утащит воркеров в OOM.

## Проверка после запуска

```sh
# 1. Узел жив и отвечает заглушкой до поколения
curl -fsS http://127.0.0.1:8079/healthz        # bootstrap

# 2. Модуль загружен
docker exec <контейнер> nginx -V 2>&1 | grep -o ngx_http_waf_module

# 3. Агент виден контуру: кадр присутствия на шине
nats sub 'WAF_STATUS.node.>' --count 1

# 4. После раскатки поколения из панели -- конфигурация применилась
docker exec <контейнер> nginx -T | head -20
```

В журнале агента при здоровом старте: подключение к шине, затем `generation applied` с
ревизией. `apply_failed` в пульсе означает, что поколение приехало, но `nginx -t` его отверг —
причина будет в журнале строкой.

## Грабли

- **Имя узла в двух местах.** `WAF_NODE_ID` у агента и `waf_node_id` в конфиге модуля. Разойдутся
  — панель покажет ноду под одним именем, а аудит запишет под другим.
- **Версия nginx.** Модуль собирается против конкретных исходников; запуск с другой версией даёт
  не ошибку загрузки, а порчу памяти. `NGINX_VERSION` в сборке образа и версия базового образа —
  одно число, менять их можно только вместе.
- **Свежая нода тянет поколение сама** из JetStream KV: рассылать вручную не нужно.
- **Заглушка на своём порту.** `:8079` выбран, чтобы не спорить с портами, которые приедут в
  поколении.
